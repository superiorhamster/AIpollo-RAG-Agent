# Agentic RAG implementation

## Goal and requirements
Implement the approved LEARN/RESEARCH/WRITE roadmap while preserving tenant isolation, immutable plan versions, exact acceptance and saved citation snapshots. Requirements: LEARN-02 approval gating, grounded academic output, private conversations, bounded Agent execution and microservice/Compose ownership.

## Scope and current behavior
The original worker retrieved six globally ranked chunks and composed one output; Plan exposed two reconstructed steps. The implementation now persists explicit workflows, completed steps, generation jobs and graph snapshots in Orchestrator. Artifact Service owns personal learning state. Workspace Service retains external reference discovery. All deployables remain in the existing Compose topology.

## Design and implementation
- **1A:** immutable accepted workflow definitions, 1–6 ordered activities, source/capability validation, lease-fenced step recovery/progress, cumulative cost reservation and fixed wall-clock deadline. Legacy plans retain their two-step definition.
- **1B:** durable queued/running/ready/failed curriculum jobs; read-only source inspection outside lock-held transactions; validated day coverage and citations; ready-before-acceptance gate; reload restoration. Days schedule the student's study, while Start creates materials immediately in order.
- **1C:** private multi-turn Socratic questions, misconception feedback, hint/solution actions and citation navigation.
- **2A/B:** pinned LangGraph 1.2.24; per-paper retrieval for 2–5 sources; balanced context; at most two gap searches across the run; paper × criterion matrix; semantic claim verification with one repair. Search/model/token/cost/deadline limits and checkpoints survive restarts. ASK retains its existing route. Research remains opt-in pending real-model evaluation.
- **3A:** pinned FSRS 6.3.3 only in Artifact Service. Stable IDs for new/legacy cards, private per-user state/history, UTC due times, idempotency keys and expected versions preventing duplicate reviews. Viewers may review privately without changing the shared artifact.
- **3B:** normalized cited concept nodes/edges, stable IDs, cycle-safe React/SVG layout, keyboard node navigation, long-label handling and multiple-source selection. Existing source-access failures remain authoritative.
- **4A:** editable external search query after insufficient evidence. Crossref is called only after explicit approval; saving a reference is a separate authorized action. Metadata never becomes RAG evidence without full-text ingestion/indexing.
- **4B:** source-grounded academic paragraphs, semantic verification of each claim, one bounded repair and explicit preview/save. Reuses durable graph progress and generation budgets.
- **4C:** private ASK research mock defense over an explicitly selected draft document, with separate target and counter-evidence anchors. Distinguishes missing citation, contradiction, unsupported assumption and clarification; student answers remain private and are not cited as source facts.
- **4D gate:** reproducible synthetic text-layer STEM corpus and extraction evaluator for symbols, indices, units, pages and coordinates. Human review and a passing extraction result are mandatory before eligible formula families can be enabled. Formula explanations/charts remain gated; OCR is outside this change.

## Security and compatibility
All APIs enforce current workspace/user/source access. Acceptance authorizes only the exact current ready version. Publication is serialized against revision/cancellation; old leases cannot publish or overwrite completed steps. Citation IDs come only from evidence supplied to that invocation. Concept SVG executes no model markup. Tutor/defense content and individual review state are excluded from shared artifact output. No cross-service table reads, model-provider calls outside Model Gateway, LangSmith uploads or external messages are introduced.

Optional objective controls omit null fields from legacy hashes. Saved chunk/segment citation modes and upstream adaptive citation behavior are preserved. Runtime database grants are restricted to owned tables/columns; curriculum publication needs UPDATE(workflow), not general revision updates.
