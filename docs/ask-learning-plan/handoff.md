# Bàn giao kỹ thuật

A/B/C giữ nguyên phạm vi và ưu tiên. Member A/B/C là vai trò tiếp nhận theo gói. Hồ sơ handoff hiện có chưa ghi tên cá nhân được phân công. Core Owner acceptance đã ghi ở [Kết quả kiểm chứng](verification.md). Extended gates dưới đây vẫn mở. Thứ tự ưu tiên A trước các gap tích hợp của C; B có thể làm song song theo contract hiện tại. C tổng hợp sau A/B. Dùng lại evidence hợp lệ.

FA01 cần bằng chứng nguồn được phép và anchor thật; FA02 cần eligibility/readiness và xác nhận an toàn; FA03 cần measured capacity; FA04 cần complete immutable preview và accessibility. Mỗi gate phải có evidence đúng tầng, pre/post state khi có write, và kết quả negative tương ứng. Không dùng model API cho CRUD, ACL, lỗi concurrency hay UI thuần. Tái sử dụng Core G0/G1/G2-Core/G3-Core.

**Residual được chấp nhận ở phạm vi hiện tại:** độ ổn định của semantic target, synthesis, event recall, provenance và citation layout như đã quan sát. Không mở vòng prompt tuning cho những sai lệch nhỏ. Nghi vấn unauthorized access hay mutation sai vẫn là lỗi blocker. **Tùy chọn:** cải thiện citation wrapping, share/export hoặc lọc Plan nếu có yêu cầu mới; giữ ngoài gate hiện tại.
